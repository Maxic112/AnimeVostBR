## Обзор

| Параметр | Значение |
|---|---|
| Пакет | `com.animevostbr` |
| minSdk / targetSdk | 26 (Android 8.0) / 34 (Android 14) |
| Язык и UI | Kotlin 1.9.22, Jetpack Compose (Material 3), одна Activity |
| Плеер | Media3 ExoPlayer 1.2.1 |
| Сеть | Retrofit 2.9 + OkHttp 4.12 + Gson, jsoup для HTML |
| Фон | WorkManager 2.9 |
| Сборка | Gradle 8.4, Android Gradle Plugin 8.2.2, JDK 17 |
| Release | R8 (минификация и сжатие ресурсов), APK ≈ 4 МБ, нативных библиотек нет — работает на любом ABI |

Один APK для телефонов, планшетов и Android TV: тип устройства определяется при запуске
(`UiModeManager`), на TV включаются управление пультом, рамки фокуса и кнопка обновления.

```
.github/workflows/         сборка, тесты и релизы в GitHub Actions
```

## Источники данных

Основной источник — недокументированный JSON API `api.animevost.org/v1`. Полное описание эндпоинтов,
форматов и особенностей — в [api.md](api.md). Главное, что учитывает код:

- `GET /last` вызывается только с `page` и `quantity=40` (иначе один тайтл или HTTP 500);
- поле `series` — Python-словарь в строке, разбирается регулярным выражением;
- `rating` — сумма оценок, звёзды = `round(rating / votes)`;
- серия определяется позицией в плейлисте: названия вроде «215-216 серия», «ОВА 1», «Фильм» не являются номерами;
- SD-ссылка в плейлисте — поле `std`;
- поиск — параметр `name`, «ничего не найдено» — HTTP 404;
- постеры `static.openni.ru` загружаются по HTTP: у хоста просрочен HTTPS-сертификат.

Видео — прямые MP4 с `video.animetop.info`. Если выбранное качество недоступно (HD у старых серий
отдаёт 404), плеер переключается на другое и запоминает выбор для следующих серий тайтла.

Full HD в плейлисте API нет. Ссылку приложение получает перед запуском серии со страницы плеера сайта
(`/frame5.php`, с откатом на зеркало, таймаут 6 секунд на сайт; пока ждём — спиннер). Файл есть не у всех
тайтлов и даже не у всех серий одного тайтла, поэтому нет ссылки или сайт недоступен — эта серия играет
в HD, а следующая снова пробует Full HD.

При ошибке воспроизведения порядок такой (`PlayerViewModel.onPlaybackFailed`):

1. ещё не испробованная ссылка того же качества со страницы плеера — там по несколько серверов на
   качество. Страница запрашивается заново, если ей больше 5 минут: подписанные ссылки живут около 3 часов,
   и после долгой паузы старая ссылка уже не работает;
2. качество ниже: Full HD → HD (только для этой серии), HD ↔ SD (запоминается для следующих серий тайтла);
3. сообщение об ошибке.

Перед каждой сменой файла плеер останавливается (`player.stop()`): аппаратный декодер телевизоров на
MStar замирает на чёрном экране, если один экземпляр переходит с 1080p на 720p. `clearMediaItems()` для
этого не подходит: пустой плеер переходит в `STATE_ENDED`, и срабатывает автопереход к следующей серии.

## Сайт, зеркало и резервный режим

API не зависит от сайта. Сайт (`animevost.org` и зеркало `vN.vost.pw`) используется для
полнотекстового поиска и как **резервный источник**, если API не отвечает.

### Режим сайта

Настройка «Сайт AnimeVost» (`Sites.mode`):

| Режим | Порядок запросов к сайту |
|---|---|
| Авто (по умолчанию) | основной сайт → зеркало; после отказа основного следующие запросы идут сразу на зеркало |
| Основной | только `https://animevost.org` |
| Зеркало | только `https://<текущее зеркало>` |

### Поиск актуального зеркала

`Sites.refreshMirror()` запускается при старте приложения и в фоновой задаче (не чаще раза в 6 часов),
а также по кнопке «Проверить зеркало». Кандидаты собираются из четырёх источников:

1. редирект со старого адреса зеркала (так сайт переезжает: `v13` → `v14`);
2. ссылки на главной `animevost.org` и на странице `/zerkalo.html`;
3. RSS зеркала — все ссылки ведут на его текущий адрес;
4. следующие три номера — на случай, если основной сайт заблокирован, а редиректа нет.

Кандидаты проверяются параллельно (ответ 200 и страница сайта AnimeVost); сохраняется живой с
наибольшим номером.

### Резервный источник

`SiteSource` разбирает HTML сайта (структура описана в [api.md](api.md#разметка-для-резервного-режима)):
ленту (`/`, `/page/N/`), карточку и серии (`/index.php?newsid=<id>`). Список серий на странице тайтла
содержит те же идентификаторы видеофайлов, что и API, поэтому ссылки на видео совпадают — это
проверяется тестом. `Repo` пробует API и при ошибке или пустом ответе переходит на сайт; если лента
пришла с сайта, над ней выводится «API не отвечает — данные с сайта …». В этом режиме нет рейтинга
(его нет в HTML), лента идёт порциями по ~10 тайтлов.

### Жанры, типы и годы

В API нет выборок по жанру, типу или году, поэтому они берутся с сайта: `/zhanr/<slug>/`,
`/tip/<slug>/`, `/god/<год>/`, следующие страницы — `…/page/N/`, по 10 тайтлов. Страница после
последней отвечает 404 — это признак конца списка (`Sites.HttpStatusException`). Разметка та же, что у
ленты (`SiteSource.parseFeed`), поэтому разбор общий. В таких карточках нет описания и числа серий;
в виде «Список» строка дозагружает полную карточку через `Repo.titleById` (API `/info`, кэш).

Списки жанров и типов зашиты в `Catalog` (как в меню сайта); годы — от текущего до 1991 и
несколько более ранних, для которых на сайте есть страницы.

## Хранение данных и фоновые задачи

### SharedPreferences (`animevostbr.xml`)

| Ключ | Содержимое |
|---|---|
| `theme_mode` | 0 — системная, 1 — тёмная (по умолчанию), 2 — светлая |
| `quality` | `FHD` / `HD` / `SD` |
| `mobile_quality` | качество в мобильной (тарифицируемой) сети; нет ключа — как по Wi-Fi |
| `grid_columns` | 0 — авто, 2…5 — плиток в ряд |
| `list_layout` | лента, поиск и каталог списком вместо плиток |
| `list_poster_size` | размер превью в списке: 0 — авто (2 на телефоне, 4 на TV), 1…5 — ширина постера 64…160 dp |
| `episode_thumbs` | список серий с превью |
| `video_resize_mode` | формат картинки в плеере: `RESIZE_MODE_FIT` (0), `FILL` (3) или `ZOOM` (4) из `AspectRatioFrameLayout` |
| `notif_enabled` | уведомления включены |
| `site_mode` | 0 — авто, 1 — основной сайт, 2 — зеркало |
| `mirror_host`, `mirror_checked_at`, `mirror_source` | текущее зеркало, время проверки, где найдено |
| `latest_release`, `update_checked_at` | ответ GitHub о последнем релизе и время проверки |
| `install_requested_at` | когда пользователя отправили выдавать разрешение на установку (см. ниже) |
| `favorites` | JSON-список `{id, title, poster, year, type}` |
| `progress` | JSON-словарь id → {позиция серии, позиция в мс, длительность, название серии, время просмотра} |
| `seen` | id → число вышедших серий (для уведомлений) |

Прогресс сохраняется каждые 5 секунд воспроизведения, при выходе из плеера и при уходе приложения в
фон. Если до конца серии меньше 30 секунд, серия считается досмотренной, и кнопка «Смотреть»
предлагает следующую.

Записи о загрузках хранятся отдельно, в `animevostbr_downloads.xml` (см. [Загрузки](#загрузки)).

### Фоновая проверка новых серий

`UpdateWorker` — уникальная периодическая задача WorkManager (`animevostbr_updates_work`), раз в
30 минут, только при наличии сети. Читает две страницы ленты (80 последних обновлений: тайтл с новой
серией поднимается наверх), сравнивает число серий у тайтлов из избранного с сохранённым и
показывает до 5 уведомлений за проверку. Нажатие на уведомление открывает страницу тайтла
(`MainActivity`, extra `title_id`).

### Обновление приложения

Источник — `GET https://api.github.com/repos/Maxic112/AnimeVostBR/releases/latest` (без токена, лимит
GitHub — 60 запросов в час с одного IP; черновики и pre-release этот эндпоинт не отдаёт). Из ответа
берутся `tag_name` (версия без `v`), `body` (список изменений из CHANGELOG), `published_at` и первый
asset с расширением `.apk`. Версии сравниваются численно по частям (`1.10.0` > `1.9.2`).

- **Когда проверяется:** при открытии экрана «Обновление»; задачей WorkManager
  `animevostbr_app_update_work` раз в сутки при наличии сети; при запуске приложения, если с прошлой
  проверки прошло больше суток (на некоторых TV WorkManager надолго откладывает задачи).
- **Оранжевая точка** — `AppUpdate.available` (Compose state): релиз новее установленной версии.
  Восстанавливается при запуске из `latest_release`, поэтому видна сразу, без сети.
- **Загрузка** — в `cacheDir/updates/` (через `.part`, с проверкой размера); готовый файл той же версии
  используется повторно.
- **Проверка перед установкой** (`AppUpdate.verify`): имя пакета, `versionCode` больше установленного и
  пересечение сертификатов подписи с установленным приложением (с учётом истории ротации ключа).
- **Установка** — `ACTION_INSTALL_PACKAGE` (запасной вариант `ACTION_VIEW`) с `content://` из
  `FileProvider` (`${applicationId}.updates`, `res/xml/update_paths.xml`).
- **Разрешение «Установка неизвестных приложений»** запрашивается через
  `ACTION_MANAGE_UNKNOWN_APP_SOURCES`. Android **завершает процесс приложения**, когда пользователь
  меняет это разрешение, поэтому перед переходом в настройки сохраняется `install_requested_at`. При
  следующем запуске (в течение 15 минут, если разрешение выдано) `AppNav` открывает экран обновления,
  и загрузка продолжается автоматически.

## Плеер

Решения плеера, которые не зависят от Android, собраны в `PlaybackRules` и покрыты JVM-тестами:

- **Стартовое качество:** качество, принудительно выбранное после ошибки, затем настройка для мобильной
  сети (если сеть тарифицируемая — `ConnectivityManager.isActiveNetworkMetered`), затем качество по
  умолчанию. Выбор в меню плеера запоминается для того типа сети, в которой он сделан.
- **Ошибка воспроизведения:** ещё не испробованная ссылка того же качества со страницы плеера сайта
  (страница запрашивается заново, если ей больше 5 минут), затем качество ниже (см.
  [Источники данных](#источники-данных)).
- **Отсчёт до следующей серии** — последние 10 секунд серии, если она длиннее минуты и есть следующая.
- **«Пропустить 90 с»** — первые 6 минут серии длиннее 10 минут. На широком экране кнопка в верхней
  панели (её достаёт пульт), на телефоне в портрете — плашка над полосой перемотки.

Остальное:

- **Пауза при уходе в фон** — по `ON_STOP` экрана плеера (Домой, другое приложение, закрытое окно
  «картинка в картинке»): видео останавливается, прогресс сохраняется.
- **Наушники** — `setHandleAudioBecomingNoisy(true)`: отключение проводных или Bluetooth-наушников
  ставит паузу.
- **Медиасессия** (`media3-session`, создаётся в `PlayerViewModel`) — кнопки гарнитуры и системные
  медиаклавиши; «следующий» и «предыдущий» переключают серии через `ForwardingPlayer`. Уведомления с
  управлением в шторке нет: для него нужен отдельный сервис.
- **Картинка в картинке** (только телефоны) — `supportsPictureInPicture` в манифесте; экран плеера
  сообщает `MainActivity`, что видео идёт. На Android 12+ окно открывается само
  (`setAutoEnterEnabled`), на более старых — из `onUserLeaveHint`. В окне скрыты все кнопки.
- **Смена файла** всегда идёт через `player.stop()`: аппаратный декодер MStar на телевизорах замирает,
  если один экземпляр переходит с 1080p на 720p.

## Синхронизация устройств

Избранное, прогресс и счётчики новых серий переносятся между двумя устройствами в одной сети, без
своего сервера (`core/Sync.kt`):

1. Одно устройство нажимает «Показать код»: открывается `ServerSocket` на случайном порту, генерируется
   код из 6 цифр, сервис объявляется в сети через NSD (`_animevostbr._tcp`, имя «AnimeVostBR · модель»).
   Ожидание — до 5 минут.
2. Второе находит его через NSD (или по адресу вручную — экран с кодом показывает IP и порт) и отправляет
   `POST /sync` с заголовком `X-Sync-Code` и своими данными в JSON (`SyncData`, поле `version`).
3. Ожидающее устройство объединяет данные (`Sync.merge`), сохраняет и отправляет результат обратно;
   второе сохраняет его. На обоих одинаковые данные.

Правила объединения: избранное — объединение по id; прогресс — для каждого тайтла запись с более поздним
`updatedAt`; счётчики серий — максимум. Удаление из избранного не передаётся. Неверный код — HTTP 403,
после 5 неверных кодов ожидание прекращается; другая версия формата — HTTP 409. Сеть — обычный HTTP
внутри локальной сети.

## Загрузки

Серии скачиваются системным `DownloadManager` (`core/Downloads.kt`): он показывает своё уведомление,
продолжает загрузку после обрыва сети и при закрытом приложении. Файлы — в
`Android/data/com.animevostbr/files/Movies/<id тайтла>/<id видео>_<качество>.mp4`, удаляются вместе с
приложением; отдельных разрешений не нужно. Для Full HD берётся свежая подписанная ссылка со страницы
плеера.

Записи (`animevostbr_downloads.xml`): id загрузки в DownloadManager, тайтл, серия, качество, путь.
Состояние берётся из DownloadManager; если записи там уже нет, загрузка считается готовой, когда файл
существует. Плеер играет скачанную серию из файла, если в нём не выбрано качество вручную; при ошибке
файла переходит к онлайн-ссылкам.

## Android TV

- Точки входа `LAUNCHER` и `LEANBACK_LAUNCHER`, баннер 320×180 dp; сенсорный экран, геймпад и
  leanback помечены `required="false"`, поэтому один APK устанавливается везде.
- Рамка фокуса (`Modifier.focusBorder`) — штатная подсветка Material почти не видна с расстояния.
- Начальный фокус: первая карточка ленты, после возврата — последняя выбранная; на странице тайтла —
  кнопка «Смотреть».
- Плеер: фокус держит сама поверхность плеера, клавиши разбираются в `handleTvKey`; кнопки
  `PlayerView` на TV фокус не получают — из `AndroidView` его нельзя вернуть в Compose.
- Кнопки, которые запускают долгие операции, не выключаются на время работы: выключенная кнопка
  теряет фокус пульта.
- Жест «потянуть для обновления» на TV отключён: прокрутка пультом оставляла его индикатор висеть над
  лентой. Обновление — кнопкой в шапке.
- Долгое нажатие «ОК» на пульте неочевидно, поэтому у каждого действия по долгому нажатию есть кнопка
  (например, «Скачать серии» на странице тайтла).

## Диагностика и мониторинг

### В приложении: «Проверка соединения»

Настройки → «Проверка соединения» — 13 последовательных проверок: API (лента, серии, карточка, поиск),
видео Full HD, HD и SD (запрос первых байт), постеры, основной сайт, зеркало, резервная лента и серии с сайта,
поиск по сайту. Если API недоступен, видео и постеры проверяются по ссылкам из резервного источника.
Сетевые ошибки переводятся в понятный текст (DNS, таймаут, сертификат, код HTTP, смена формата), а
сверху выводится итог.

### На компьютере: `tools/api_check.py`

```bash
python tools/api_check.py           # полный отчёт
python tools/api_check.py --quiet   # только итог
```

Скрипт проверяет доступность и **формат** ответов API (обязательные поля, известные особенности вроде
ответа на `/last` без параметров и 404 при пустом поиске), видео, постеры, сайт, находит актуальное
зеркало (сообщает о смене адреса) и наличие списка серий на странице тайтла. Результаты дописываются
в `logs/api_health.log` и `logs/api_health.jsonl` (папка не попадает в git). Код выхода: 0 — всё
работает, 1 — предупреждения, 2 — что-то сломано. Нужен только Python 3.8+ без зависимостей.

Последняя проверка — страница плеера сайта: есть ли блок со ссылками SD и HD и отвечает ли Full HD. Если
сайт поменяет разметку, приложение молча потеряет Full HD и запасные серверы, а скрипт это покажет.

### Ежедневно в GitHub Actions

Workflow [`.github/workflows/health.yml`](../.github/workflows/health.yml) запускает `api_check.py`
каждый день в 09:17 по Москве и вручную (Actions → Source health → Run workflow). Код 2 — запуск
падает, и GitHub присылает письмо; предупреждения (например, смена зеркала) видны в логе. Расписание
GitHub отключает после 60 дней без коммитов в репозитории — тогда его нужно включить на вкладке Actions.

## Сборка, подпись и релизы

### Локальная сборка

Требуются JDK 17 и Android SDK (platform 34). Путь к SDK задаётся `ANDROID_HOME` или `local.properties`.

```bash
./gradlew testDebugUnitTest assembleDebug     # тесты и отладочный APK
sh tools/build_release.sh                     # тесты и подписанный AnimeVostBR-v<версия>.apk
```

### Ключ подписи

Release-сборка подписывается в Gradle (`app/build.gradle.kts`, схемы v2 + v3). Параметры берутся из
переменных окружения, а если их нет — из файла `keystore/keystore.properties` (папка `keystore/` в git
не попадает):

```properties
storeFile=animevostbr-release.jks
storePassword=<пароль хранилища>
keyAlias=animevostbr
keyPassword=<пароль ключа>
```

| Переменная окружения | Значение |
|---|---|
| `RELEASE_STORE_FILE` | путь к `.jks` |
| `RELEASE_STORE_PASSWORD` | пароль хранилища |
| `RELEASE_KEY_ALIAS` | псевдоним ключа |
| `RELEASE_KEY_PASSWORD` | пароль ключа |

Без ключа release-сборка остаётся неподписанной (`app-release-unsigned.apk`). Debug-сборки
подписываются release-ключом, если он доступен, чтобы их можно было ставить поверх установленного
релиза.

> Android устанавливает обновление поверх существующей версии только при совпадении ключа подписи.
> Потеря ключа означает, что пользователям придётся удалить приложение вместе с избранным и прогрессом,
> поэтому храните резервную копию хранилища и паролей.

Отпечаток сертификата официальных сборок (SHA-256), им можно проверить подлинность APK
(`apksigner verify --print-certs`):

```
63:CA:ED:8B:CA:A0:5A:C4:86:E4:99:BC:CB:0B:BA:DC:F9:CF:79:08:4C:B5:2E:B0:29:04:B5:94:00:40:6A:D8
```

### GitHub Actions

Workflow [`.github/workflows/build.yml`](../.github/workflows/build.yml):

| Событие | Что происходит |
|---|---|
| push в `main`, pull request, ручной запуск | юнит-тесты, debug APK и проверочная release-сборка (без подписи); debug APK — в артефактах запуска |
| push тега `v*` | проверка, что тег совпадает с `versionName`; тесты; подписанный release; проверка подписи `apksigner`; GitHub Release с APK и описанием из `CHANGELOG.md` |

Секреты репозитория (Settings → Secrets and variables → Actions):

| Секрет | Значение |
|---|---|
| `KEYSTORE_BASE64` | содержимое `.jks` в base64 |
| `KEYSTORE_PASSWORD` | пароль хранилища |
| `KEY_ALIAS` | псевдоним ключа |
| `KEY_PASSWORD` | пароль ключа |

### Выпуск новой версии

1. Увеличьте `versionCode` (обязательно, иначе обновление не установится) и `versionName` в
   `app/build.gradle.kts`.
2. Добавьте раздел версии в `CHANGELOG.md` — он станет описанием релиза.
3. Закоммитьте изменения и создайте тег: `git tag v<versionName>` → `git push origin main --tags`.
4. Workflow соберёт, подпишет и опубликует APK на странице Releases. Установленные приложения увидят
   новую версию при следующей ежедневной проверке или сразу на экране «Обновление».

> Встроенное обновление берёт **последний опубликованный** релиз и первый `.apk` в нём. Не публикуйте
> релиз с APK, подписанным другим ключом: приложение откажется его ставить.

## Тестирование

JVM-тесты (`ParsersTest.kt` — 17, `PlaybackRulesTest.kt` — 7, `FullHdTest.kt` — 5, `SyncTest.kt` — 4,
`AppUpdateTest.kt` — 3, `CatalogTest.kt` — 2, `ScheduleTest.kt` — 2) проверяют парсеры на реальных
ответах серверов из `app/src/test/resources/fixtures` и логику приложения:

- плеер: стартовое качество с учётом мобильной сети, запасная ссылка, свежесть страницы плеера, порядок
  снижения качества, отсчёт до следующей серии и «Пропустить 90 с»;
- синхронизация: правила объединения и настоящий обмен через сокет на `127.0.0.1`, включая неверный
  код и остановку после 5 ошибок;
- расписание: группировка по дням в часовом поясе, номер серии из названия, тайтлы без даты;

- лента, карточка, поиск и ответ «ничего не найдено»;
- плейлист: HD/SD (`std`), нумерация по позиции для «ОВА», «Фильм», «215-216 серия», «1-40 серии»,
  совпадение серий плейлиста и ленты;
- поле `series`, `timer = 0`, ранжирование подсказок, разбор названия на части;
- резервный источник: лента и карточка из HTML сайта, совпадение серий сайта и API, поиск адреса зеркала;
- каталог: страница жанра с сайта, пути выборок;
- Full HD: ссылка со страницы плеера (упрощённая копия без настоящих токенов и IP), запасной шаблон
  без файла не считается;
- обновление: разбор ответа GitHub `releases/latest` (пропуск черновиков, pre-release и релизов без APK),
  сравнение версий.

```bash
./gradlew testDebugUnitTest
```

HTML-эталоны сайта сокращены до разметки, которую разбирает приложение. Чтобы проверить работу
резервного режима на устройстве, временно укажите в `ApiClient` недоступный адрес API, соберите
debug-версию и откройте «Проверку соединения».

## Разрешения и приватность

| Разрешение | Зачем |
|---|---|
| `INTERNET` | каталог, постеры, видео |
| `ACCESS_NETWORK_STATE` | фоновая проверка запускается только при наличии сети |
| `WAKE_LOCK` | требуется WorkManager |
| `POST_NOTIFICATIONS` | уведомления о новых сериях (Android 13+) |
| `REQUEST_INSTALL_PACKAGES` | установка обновлений из GitHub Releases; пользователь выдаёт его сам в настройках Android |

Нет аккаунтов, рекламы, аналитики и телеметрии. Избранное, прогресс и настройки хранятся только на
устройстве. Запросы идут только к серверам AnimeVost и, для проверки обновлений, к GitHub
(`api.github.com`, загрузка APK — `github.com` и его CDN). Видео и постеры загружаются по HTTP, поэтому в
манифесте включён `usesCleartextTraffic`.

Синхронизация работает только внутри локальной сети и только пока открыт экран с кодом; данные уходят
на устройство, которое ввело код. Загрузки используют системный DownloadManager и папку приложения —
новых разрешений не требуется.

## Известные ограничения

- API закрытый и может измениться; парсеры терпимы к изменениям, а `tools/api_check.py` помогает быстро
  найти расхождение.
- Сайт может быть недоступен у отдельных провайдеров — тогда помогает зеркало или другая сеть.
- В резервном режиме нет рейтинга, а уведомления о новых сериях работают только через API.
- Поиск API — по подстроке: знаки препинания мешают (их обрабатывает резервный поиск по сайту),
  на запросы из двух букв — не больше 50 совпадений.
- Синхронизация — только по команде и в одной сети; удаление из избранного не передаётся. Поиск
  устройства (NSD) не работает в сетях, где роутер блокирует multicast, — тогда адрес вводится вручную.
- Отсчёт до следующей серии нельзя отменить: можно перейти раньше или выйти из плеера.
- Android 7.1 и старше не поддерживаются; приложения нет в Google Play.
